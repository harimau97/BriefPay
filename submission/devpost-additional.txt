EXPLAIN HOW YOUR PROJECT MEETS THE MAIN TECHNOLOGY REQUIREMENT
Name each PayPal tool and each AI tool, and what it does.
================================================================================

PayPal developer platform, sandbox only. The app refuses PAYPAL_ENVIRONMENT=LIVE.

- PayPal JavaScript SDK. The checkout button is created with intent=authorize and currency USD. Buyer approval records an authorization hold. It does not capture.
- Orders v2. The server creates an order with intent AUTHORIZE, then calls authorize after the buyer approves.
- Payments v2. After every acceptance criterion passes, server code captures that authorization with a stable PayPal-Request-Id. Cancel voids the authorization. A job that was already captured is refunded instead.
- Invoicing v2. After capture, the server can record an invoice as a receipt for money already captured. The invoice does not request another payment.
- PayPal Agent Toolkit (@paypal/agent-toolkit), sandbox only. A separate step may draft an invoice with invoice create, get, and list. The server checks that the draft amount matches the job budget before send and record-payment. The review model does not receive these tools.

AI:

- Vercel AI SDK and Anthropic. The review model is Claude Haiku 5.5, model id claude-haiku-5-5, through ANTHROPIC_API_KEY.
- The model opens the freelancer's delivery URL and returns a pass or fail for each acceptance criterion, with evidence. It cannot call PayPal. Capture, void, and refund stay in server code and run only from the job state.
- If the model response is not a structured verdict, the server scores the same page observation itself. Capture still runs only after a pass.
- Without KERNEL_API_KEY, review reads the page HTML directly. It does not measure the page in a 390px browser.

TESTING INSTRUCTIONS OR CREDENTIALS
Paste your sandbox Personal buyer email and password over the two blank lines. Do not put live PayPal credentials here.
================================================================================

No password is required for the BriefPay demo roles.

1. Open https://meganesoftware.cc/briefpay/
2. Press Start as client. The header can switch between Client and Freelancer.
   Demo client: client@demo.com
   Demo freelancer: freelancer@demo.com
3. Open a job whose badge is Draft, or press New job and keep the defaults. The defaults are "Landing page redesign", USD 150, and four acceptance criteria. Do not open a job that is already Captured or Voided.
4. Press the PayPal button. In the sandbox.paypal.com window, sign in with this sandbox Personal buyer and approve the authorization:

   Sandbox buyer email:
   Sandbox buyer password:

   Approval places a hold. The badge becomes Authorized and the capture ID stays empty.
5. Switch to Freelancer, press Accept job, press Fail example, then Submit delivery.
   Fail URL: https://meganesoftware.cc/briefpay/demo/fail
6. Press Run AI review. The log names claude-haiku-5-5. The badge becomes Revision. Capture is not called, and the capture ID stays empty.
7. Press Pass example, submit again, and press Run AI review.
   Pass URL: https://meganesoftware.cc/briefpay/demo/pass
8. Every criterion should pass. Server code then captures the authorization. The badge becomes Captured and a capture ID appears.
9. The timeline lists Created, Authorization hold, Accepted, Delivery submitted, Verification started, Verification passed, and Captured.

This is a PayPal sandbox authorization hold, then capture. It is not licensed escrow. The receipt invoice, if present, is not a second charge. A missing receipt invoice does not undo a completed capture.

Do not press Cancel job or Force payout during the fail step. Cancel releases the hold. Force payout captures the full amount after a failed review.

================================================================================
OVERALL EXPERIENCE RATING: WHY
================================================================================

The sandbox Orders v2 authorize flow and the Payments v2 authorization capture did what the product needed: buyer approval places a hold, and a separate server call captures it only after review. The JavaScript SDK button with intent=authorize was clear.

Two parts cost time. A Korean sandbox buyer paying a Korean sandbox merchant is treated as a domestic payment and is declined, so the buyer account had to be a United States Personal sandbox account. The authorize response also omitted the amount unless Prefer: return=representation was set, and reusing one PayPal-Request-Id replayed that incomplete response. After those two fixes, create, authorize, and capture completed in the sandbox.

The Agent Toolkit invoice draft is a separate receipt step. Capture does not depend on it.
